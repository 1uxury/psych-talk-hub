# PsychTalk Hub — AI 开发者实施计划

日期：2026-10-03｜目标：三天完成可演示的 MVP｜建议投入：18–24 小时

产品依据：[英文设计文档](design-document.md)、[中文设计文档](design-document.zh-CN.md)。技术依据：[技术栈](tech-stack.md)。仓库规则：[AGENTS.md](../AGENTS.md)。

目录说明：本文提到的 backend、frontend、memory-bank 和工作流目录均相对仓库根目录；Markdown 文档链接相对当前文件所在目录。中英文设计文档均位于 memory-bank，不另建带 @ 前缀的文件或设计副本。

本文仅包含执行指令和验证要求，不包含应用代码、配置代码、伪代码或命令片段。所有验证均为将来实施时的要求，不代表已经执行。

## 执行规则

- 按编号推进，每次只完成一个步骤。先阅读已有实现，避免重复创建或覆盖用户工作。
- 写任何应用代码前，必须完整阅读 memory-bank/architecture.md 和 memory-bank/design-document.md。首次执行先完成第 01 步，补齐初始架构记录。
- 每一步都必须执行对应验证，并在 memory-bank/progress.md 记录实际结果。失败时先修复，再进入依赖该结果的步骤；外部条件不具备时标记为未验证，只继续不依赖该条件的工作。
- 使用 Django 自带测试框架、DRF 测试工具和 PostgreSQL。普通自动化测试模拟 Crossref；真实外部集成另行验证。前端交互可以通过可重复的浏览器操作验证，不增加大型测试工具链。
- 每完成重大功能，立即更新架构记录。三个里程碑还需检查记录完整性；区分已实现、计划中和未验证事项，不记录密钥。
- 产品界面使用英文。只实现两个公开 React 页面和 Django Admin，不增加会员、报名、支付、聊天、AI 推荐或独立管理面板。
- 每步完成后向用户简要报告改动、测试结果和遗留问题。未经测试，不得标记该步完成。

## 第一阶段：建立可运行的浏览路径

建议第 1 天完成本阶段；以约 6–8 小时为预算，进度以验证结果为准。

### 01. 核对必读文档并初始化架构记录

- **指令：** 完整阅读 memory-bank/design-document.md 和 memory-bank/architecture.md。若架构记录为空，先记录当前仅有文档的状态、计划架构和目录职责；已有内容先阅读再补充。检查 memory-bank/progress.md，并记录本次准备工作。使用当前设计文档，不复制另一份设计文件。
- **验证测试：** 设计、架构和进度文件都存在且可读取；架构记录已补齐初始状态，进度记录只包含已完成的准备事项；两份设计文档规则一致，链接有效，没有带 @ 前缀或重复设计文件。

### 02. 建立仓库和目录骨架

- **指令：** 检查 Git 状态，未初始化时建立本地仓库。创建 backend、frontend 和工作流目录，按 AGENTS.md 设置忽略规则，保留现有文档。通过功能分支开展后续开发。
- **验证测试：** 仓库状态可读取，现有文档未丢失；本地环境文件、虚拟环境、安装依赖和构建产物不会进入提交。仅包含空目录时，不误报其已被 Git 跟踪。

### 03. 建立 Django 最小项目

- **指令：** 按技术栈选择 Python 和后端依赖，建立隔离环境、Django 项目及单个 events 业务应用。区分本地开发与 Linux 部署依赖，不要求在 Windows 上运行 Gunicorn。
- **验证测试：** 依赖版本符合选型，Django 系统检查通过，本地服务能启动，默认 Admin 登录页可访问；没有引入第二个业务后端或额外认证框架。

### 04. 配置独立数据库与环境变量

- **指令：** 连接 PostgreSQL，使用 django-environ 读取配置，启用时区支持。分开开发、测试和生产数据库，提供不含真实值的环境变量示例；生产必需配置缺失时应明确失败。
- **验证测试：** 数据库连接成功，基础迁移可执行；测试数据库与开发数据库不同；缺少生产密钥或数据库地址时不能静默使用不安全默认值。检查仓库中没有真实凭据。

### 05. 建立活动模型

- **指令：** 建立 Event，保存标题、简介、主题、开始时间和讲者。标题与开始时间必填，使用有时区的时间，不新增结束时间或发布审批状态。
- **验证测试：** 有效活动可保存并读取；空白标题和缺失时间在表单或业务入口被拒绝；一次 UTC 时间存取保持同一时刻；迁移可在空数据库执行。

### 06. 建立共享资源模型

- **指令：** 建立 Resource，保存标题、作者、年份、原文链接、可选 DOI、类型和元数据来源。标题和 HTTP(S) 原文链接必填；无 DOI 使用空值，作者和年份允许缺失。
- **验证测试：** 论文与手动资料都可保存；两个无 DOI 资源不会互相冲突；无标题或不支持的链接协议被拒绝；缺失作者和年份可以正常序列化。

### 07. 建立活动资源关联

- **指令：** 建立 EventResource，保存活动、资源、推荐理由和数字展示顺序。建立活动与资源组合的数据库唯一约束，展示顺序默认为零，同值按关联 ID 升序。
- **验证测试：** 同一资源可关联两个活动，同一活动不能重复关联同一资源；两个活动的推荐理由可以不同；不同顺序值及相同顺序值都得到确定的排序。

### 08. 配置基础 Admin 管理

- **指令：** 在 Django Admin 注册模型，支持活动编辑、手动资源添加及选择已有资源。活动时间表单标明伦敦时区，保存后提供公开页面地址；页面未实现时先验证生成的地址。
- **验证测试：** 管理员可创建活动和手动资料，关联已有资源；无效输入显示字段错误；未登录者不能进入管理操作；时间按伦敦时区输入后保存的是正确时刻。

### 09. 建立可重复的演示数据

- **指令：** 提供独立的示例数据导入入口，生成至少一场即将举办活动、一场历史活动及每场三条资料。使用明确的示例标识，日期相对导入时刻安排，不在每次部署时重置数据。
- **验证测试：** 连续导入两次不增加重复记录；已有手动修改不被覆盖；示例中同时存在未来和过去活动，每场资源数量满足要求，虚构内容被明确标注。

### 10. 实现活动列表只读接口

- **指令：** 实现公开活动列表接口，返回稳定的活动标识、展示所需信息和资源数量。记录实际响应契约，使用聚合获取资源计数，不为每个活动分别查询资源。
- **验证测试：** 无登录请求可以读取；零资源活动仍会返回且数量为零；活动计数准确；增加活动数量时，数据库查询次数不随每张卡片线性增长。

### 11. 实现活动详情只读接口

- **指令：** 实现公开活动详情接口，返回活动信息、按关联顺序排列的资源和该活动的推荐理由。使用关联预加载，并在架构记录中补充接口职责和字段约定。
- **验证测试：** 活动只包含自己的资料；共享资源显示当前活动的推荐理由；缺失作者和年份不会报错；零资料返回空集合，不存在的活动返回未找到，查询次数不随资源数线性增长。

### 12. 限制公开接口方法

- **指令：** 将两个公开接口限制为读取、响应头和接口说明请求，不暴露创建、编辑或删除能力，不因使用通用组件而自动开放 CRUD。
- **验证测试：** 分别使用匿名用户和已登录管理员向公开接口发出新增、修改和删除请求；均被拒绝，数据库记录和内容不变。正常读取仍可用。

### 13. 建立 React 项目与本地代理

- **指令：** 建立 JavaScript 版 Vite React 项目，加入 React Router 的声明式路由，保留 ESLint，使用普通 CSS。将相对 API 请求通过本地代理转发至 Django，不引入跨域包。
- **验证测试：** 前端开发页面能打开，同源路径可读取真实后端活动；前端 lint 和生产构建通过；没有添加 TypeScript、状态管理库或独立 Node.js 后端。

### 14. 建立请求状态与页面路由

- **指令：** 为首页和活动详情建立共用请求模块，检查 HTTP 状态，区分加载、成功、未找到与失败；切换页面时取消过期请求。其他前端地址展示未找到状态。
- **验证测试：** 人为延迟和失败的请求产生对应状态；快速切换两个活动后，旧响应不能覆盖新活动；不存在的活动展示未找到，不误报为空资料；浏览器返回可用。

### 15. 实现首页活动分组

- **指令：** 实现设计文档规定的标题、Upcoming 和 Past 分组及卡片。以一次页面渲染采用的同一当前时刻分组，Upcoming 时间升序、Past 时间降序，时间相同按活动 ID 升序。
- **验证测试：** 用固定当前时刻验证未来、过去和恰好开始的活动归类；验证两个分组排序和同时间排序；只有一个分组有数据以及完全无活动时，均显示规定提示。

### 16. 实现详情页基本阅读

- **指令：** 展示活动信息、资源类型、标题、作者、年份、推荐理由和原文操作。没有推荐理由时省略对应区域；原文在新标签页打开；展示示例标识和独立项目说明。
- **验证测试：** 实际浏览一场活动并打开原文；作者和年份缺失时显示规定文案；资源顺序与接口一致；无资源活动仍展示活动信息；新标签页行为有可访问提示。

### 17. 验证第一个里程碑与部署可行性

- **指令：** 从 Admin 创建一条资料，重新加载公开页面确认可见。核对目标托管环境的 Python、Node.js、数据库与构建能力，使用已有且已授权的资源尝试后端最小部署；完整静态集成留到第三阶段。更新架构记录和 AGENTS.md 中已变化的仓库状态。
- **验证测试：** 本地完整浏览路径可重复完成；依赖、数据库和部署限制有实际核对记录。可用远程环境中的 Admin 登录页能响应；没有可用账号或资源时明确记为外部阻塞，不声称 Demo 已部署。

## 第二阶段：完成搜索与 DOI 管理闭环

建议第 2 天完成本阶段；以约 6–8 小时为预算。

### 18. 实现当前活动内的标题搜索

- **指令：** 在已有资源集合中执行标题包含搜索，忽略大小写及查询两端空格。清空搜索后恢复原始顺序；无资源时不显示搜索框，无结果时提供清空操作。
- **验证测试：** 相同词的大小写变体和带两端空格的查询结果一致；作者名称不会被当作标题命中；其他活动的资料不出现；清空后数量和顺序恢复，无结果文案正确。

### 19. 建立 DOI 输入规范化

- **指令：** 接受纯 DOI 与规定的 DOI 链接，统一空白、链接前缀和大小写后再查询或匹配已有记录。只允许固定 Crossref 目标，不把任意输入当成请求网址。
- **验证测试：** 同一 DOI 的纯文本、链接和大小写形式归一到同一标识；空输入和非 DOI 链接在请求前被拒绝；带合法标点的 DOI 不被粗暴截断；无效输入不会触发网络访问。

### 20. 实现 Crossref 成功响应转换

- **指令：** 在独立服务模块中获取元数据，设置技术栈规定的连接和读取超时，转换为资源所需字段；作者用于展示，缺失作者或年份保留为空，不导入摘要或生成结论。
- **验证测试：** 模拟完整、缺作者、缺年份和多作者响应，结果符合资源字段规则；核对请求目标和超时设置；缺少必需标题或原文链接时，预览明确要求补充，查询阶段不写数据库。

### 21. 实现 Crossref 错误转换

- **指令：** 分别处理记录不存在、请求过多、上游错误、无效响应、连接失败和超时。转换为设计文档的提示，保留输入，不自动循环重试，不将内部异常详情暴露给用户。
- **验证测试：** 对上述每种情况模拟一次失败，检查提示和重试或手动添加入口；每次用户动作只触发一次外部请求；所有失败后资源与关联数量不变。

### 22. 实现原子保存与已有资源复用

- **指令：** 将资源匹配或创建以及活动关联保存放在短事务中。已有 DOI 复用共享资源且不覆盖元数据；已有关联返回原记录。外部请求不得处于保存事务中。
- **验证测试：** 新 DOI 产生一条资源和一条关联；同一 DOI 加入另一活动只增加关联；重复提交当前活动不增加记录；人为使关联保存失败，新资源也回滚；已有共享元数据不改变。

### 23. 验证并发保存

- **指令：** 使用 PostgreSQL、独立数据库连接和协调起点验证竞争保存；将预期唯一冲突在事务回滚后转换为已存在结果，不吞掉其他数据库错误。
- **验证测试：** 两个请求同时向同一活动加入同一 DOI，最终只有一条资源和一条关联；同时加入两个活动，最终只有一条资源和两条关联；请求都获得可解释结果，不留下失败事务状态。

### 24. 加入 Admin DOI 预览页面

- **指令：** 在 Django Admin 内增加两步导入表单，始终显示目标活动。第一步获取并预览资料，允许补充必需字段和推荐理由；预览状态使用受保护的服务器端状态，不信任提交的活动标识。
- **验证测试：** 获取成功和失败都不新增数据库记录；取消后返回活动且不保存；必需字段缺失时不能继续保存；修改目标活动参数不能把资料导入无权管理的活动。

### 25. 接通 Admin 确认保存

- **指令：** 将确认操作接入第 22 步保存能力，重新验证提交字段和目标权限。成功后显示规定提示和公开页面链接；失败保留输入。获取和保存中禁用重复提交控件。
- **验证测试：** 预览后确认才写入，重新加载公开页面立即可见；重复确认不会重复关联；无效或过期预览不保存；保存失败保留编辑内容；按钮恢复后仍能重新操作。

### 26. 完成共享元数据修改与排序

- **指令：** 修改共享 Resource 前显示其影响所有引用活动的提示；活动推荐理由和数字顺序仅修改关联记录，使用既有 Admin 表单，不增加拖拽功能。
- **验证测试：** 修改共享标题后两个引用活动都更新且提示存在；只改活动 A 的理由或顺序，活动 B 不变；同值排序仍确定，默认值和自定义值都生效。

### 27. 完成移除关联

- **指令：** 提供从当前活动移除资料的操作和规定确认文案，仅解除关联，不删除共享资源，不提供此流程之外的公开删除入口。
- **验证测试：** 取消确认时数据不变；确认移除后当前活动计数减少，其他活动仍有该资源，共享资源记录仍存在；未授权移除被拒绝。

### 28. 补齐后台权限与 CSRF 验证

- **指令：** 检查创建、查询导入、确认保存、共享编辑、排序和移除等所有自定义管理入口；使用 Admin 权限包装和对应模型权限，持久化修改仅通过受保护的提交进行。
- **验证测试：** 匿名用户和无对应权限的 staff 用户不能操作；启用真实 CSRF 检查后，缺少或伪造令牌的提交失败；通过读取请求不能保存或移除；数据库均不改变。

### 29. 完成真实 DOI 集成验证

- **指令：** 使用开发环境与一个已确认存在的真实 DOI，完成查询、预览、确认、公开阅读与重复导入。核对来源标题、作者和原文地址，继续把 CI 测试保持为模拟外部响应。
- **验证测试：** 真实服务返回的字段与来源一致；第二次导入不增加重复数据；查询不可用时已有公开资料仍可读。网络不可用时记录此项未验证，不用模拟测试冒充真实集成。

### 30. 验证第二个里程碑

- **指令：** 完整走通搜索、DOI 导入、手动添加、共享编辑和关联移除，更新 memory-bank/architecture.md 中的服务边界、权限与测试覆盖，并更新 memory-bank/progress.md。产品行为有调整时，同步 memory-bank 中的两份设计文档。
- **验证测试：** 后端相关测试全部通过，浏览器操作可重复；架构与进度记录符合实际文件、接口和验证结果；尚未完成的内容仍明确标为计划中，两份设计文档的规则不存在冲突。

## 第三阶段：部署、检查和交付

建议第 3 天完成本阶段；以约 6–8 小时为预算。停止新增功能，只处理未通过的验收项。

### 31. 完善公开页面状态

- **指令：** 按设计文档补齐加载、全空、单组为空、无资料、搜索无结果、活动不存在及请求失败。失败提供重试，空数据不误显示为异常，异常不误显示为空数据。
- **验证测试：** 通过固定测试数据和可控网络失败逐项触发上述状态；核对英文文案和操作；重试成功后错误消失，离开页面后的取消请求不显示为用户错误。

### 32. 验证时间与浏览器导航

- **指令：** 检查所有日期明确使用伦敦时区，保持首页和详情状态一致；验证浏览器前进、返回和活动页面直接访问。不要额外增加实时更新。

### 33. 完善视觉与可访问性

- **指令：** 实现确认的颜色、系统字体、字号、间距、最大宽度和断点。确保搜索框有标签，原文链接说明新标签页行为，焦点清晰，错误附带文字，不加入装饰性图片或复杂动画。

### 34. 锁定依赖并建立 CI

### 36. 增加健康检查与安全日志
