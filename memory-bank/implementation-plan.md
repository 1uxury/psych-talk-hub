# PsychTalk Hub — AI 开发者实施计划

日期：2026-10-03｜版本：v0.2｜目标：三天交付可审阅版本，完整 MVP 按验收补齐｜建议投入：18–24 小时

产品依据：[英文设计文档](design-document.md)、[中文设计文档](design-document.zh-CN.md)。技术依据：[技术栈](tech-stack.md)。仓库规则：[AGENTS.md](../AGENTS.md)。

目录说明：本文提到的 backend、frontend、memory-bank 和工作流目录均相对仓库根目录；Markdown 文档链接相对当前文件所在目录。中英文设计文档均位于 memory-bank，不另建带 @ 前缀的文件或设计副本。

本文仅包含执行指令和验证要求，不包含应用代码、配置代码、伪代码或命令片段。所有验证均为将来实施时的要求，不代表已经执行。

## 执行规则

- 按编号推进，每次只完成一个步骤。先阅读已有实现，避免重复创建或覆盖用户工作。
- 写任何应用代码前，必须完整阅读 memory-bank/architecture.md 和 memory-bank/design-document.md。首次执行先完成第 01 步，补齐初始架构记录。
- 每一步都必须执行对应验证，并在 memory-bank/progress.md 记录实际结果。失败时先修复，再进入依赖该结果的步骤；外部条件不具备时标记为未验证，只继续不依赖该条件的工作。
- 使用 Django 自带测试框架、DRF 测试工具和 PostgreSQL。普通自动化测试模拟 Crossref；真实外部集成另行验证。前端交互可以通过可重复的浏览器操作验证，不增加大型测试工具链。
- 每完成重大功能，立即更新架构记录。三个里程碑还需检查记录完整性；区分已实现、计划中和未验证事项，不记录密钥。
- 产品界面使用英文。只实现两个公开 React 页面和 Django Admin，不增加会员、报名、支付、聊天、AI 推荐或独立管理面板。
- 使用独立 Python 3.13 与 PostgreSQL 17 环境，保留旧安装。线上仅使用免费 Render 服务；账号连接、免费额度或数据库版本不可用时记录外部阻塞，不自动开通付费方案。
- API 字段、类型、空值与错误以技术栈的 Public API contract 为唯一详细契约；不在实施时临时选择另一种响应结构。DOI、预览、权限和示例规则均按已修订的产品设计与技术栈执行。
- 三天优先完整核心路径、关键测试、GitHub 和可复现说明。线上验收或视频未完成时列为后续待办，不降低权限、事务、CSRF 或去重验证标准，不宣称完整 MVP 已完成。
- 每步完成后向用户简要报告改动、测试结果和遗留问题。未经测试，不得标记该步完成。

## 第一阶段：建立可运行的浏览路径

建议第 1 天完成本阶段；以约 6–8 小时为预算，进度以验证结果为准。

### 01. 核对必读文档并初始化架构记录

- **指令：** 完整阅读 memory-bank/design-document.md 和 memory-bank/architecture.md。若架构记录为空，先记录当前仅有文档的状态、计划架构和目录职责；已有内容先阅读再补充。检查 memory-bank/progress.md，并记录本次准备工作。使用当前设计文档，不复制另一份设计文件。
- **验证测试：** 设计、架构和进度文件都存在且可读取；架构记录已补齐初始状态，进度记录只包含已完成的准备事项；两份设计文档规则一致，链接有效，没有带 @ 前缀或重复设计文件。

### 02. 建立仓库和目录骨架

- **指令：** 检查 Git 状态，未初始化时建立本地仓库。创建 backend、frontend 和工作流目录，按 AGENTS.md 设置忽略规则，保留现有文档。通过功能分支开展后续开发。
- **验证测试：** 仓库状态可读取，现有文档未丢失；本地环境文件、虚拟环境、安装依赖和构建产物不会进入提交。仅包含空目录时，不误报其已被 Git 跟踪。

### 03. 建立 Django 最小项目

- **指令：** 建立独立 Python 3.13 环境、Django 项目及单个 events 业务应用，保留现有 Anaconda 和旧 Python。首次安装即锁定后端直接及传递依赖；区分 Windows 开发与 Linux 部署依赖，不要求本地运行 Gunicorn。数据库、迁移和 Admin 登录验证留到第 04 步，不把临时 SQLite 数据作为验收结果。
- **验证测试：** 独立环境的解释器及依赖版本符合选型，旧环境未被替换；Django 系统检查通过，锁定文件不含本机路径或凭据，安装结果可核对；没有第二个业务后端或额外认证框架。

### 04. 配置独立数据库、基础 CI 与健康检查

- **指令：** 使用独立 PostgreSQL 17 实例，保留旧数据库并核对端口。使用 django-environ 分开开发、测试及生产配置，启用时区支持并提供无真实值的环境变量示例。执行基础迁移后验证 Admin 登录页；建立 PostgreSQL 17 的基础后端 CI，执行系统检查、测试和迁移遗漏检查。提供应用及数据库健康检查，不访问 Crossref。生产必需配置缺失时明确失败。
- **验证测试：** 开发连接与基础迁移成功，测试库与开发库不同，旧数据库服务未被替换；Admin 登录页可访问；初始 CI 检查通过。数据库可用时健康检查成功，模拟不可用时返回非成功状态且不泄漏细节；缺少生产密钥或数据库地址时不能使用不安全默认值，仓库无真实凭据。

### 05. 建立活动模型

- **指令：** 建立 Event，保存标题、简介、主题、开始时间、讲者、示例标记及稳定导入标识。标题与开始时间必填，其余展示文字可为空，示例标记默认为假，普通活动不填导入标识。使用有时区的时间，不新增结束时间或发布审批状态。
- **验证测试：** 有效活动可保存并读取；空白标题和缺失时间被拒绝，简介、主题、讲者缺失可保存；普通活动不显示示例标签，稳定导入标识非空时唯一、多个空标识不冲突；UTC 存取保持同一时刻，迁移可在空数据库执行。

### 06. 建立共享资源模型

- **指令：** 按技术契约建立 Resource，保存标题、作者展示字符串、年份、原文链接、可选且唯一的 DOI、两种资料类型、两种来源及可空的稳定导入标识。标题和 HTTP(S) 链接必填；缺失作者为空字符串，年份与 DOI 为空值；年份限定为 1–9999。手动资料不按标题或 URL 自动合并，可选择已有资源。
- **验证测试：** 两种类型及来源均可保存；多个无 DOI 或空导入标识不冲突，重复非空 DOI/导入标识被数据库拒绝；同标题或 URL 的手动资料仍可独立创建；无标题、不支持的协议或越界年份被拒绝，缺失作者及年份按契约序列化。

### 07. 建立活动资源关联

- **指令：** 建立 EventResource，保存活动、资源、推荐理由和数字展示顺序。建立活动与资源组合的数据库唯一约束，展示顺序默认为零，同值按关联 ID 升序。
- **验证测试：** 同一资源可关联两个活动，同一活动不能重复关联同一资源；两个活动的推荐理由可以不同；不同顺序值及相同顺序值都得到确定的排序。

### 08. 配置基础 Admin 管理

- **指令：** 在 Django Admin 注册模型，支持活动编辑、手动资源添加及选择已有资源。时间表单标明伦敦时区，保存后提供公开地址；未实现公开页面时先验证地址。禁用 Resource 单条、批量及直接地址删除，包括超级管理员；活动单条及批量删除需确认且仅删除活动与关联，保留共享资源。使用设计文档规定的删除确认文案。
- **验证测试：** 管理员可创建活动、手动资料并关联已有资源；无效输入显示字段错误，未登录者不能管理；伦敦时间存储正确。确认前活动数据不变；删除一场活动后，其关联消失而 Resource 与另一场活动的关联保留；资源三种删除入口均被拒绝。

### 09. 建立可重复的演示数据

- **指令：** 开发者精选并核对真实论文、文章及链接，为两场虚构心理学讲座各准备至少三条资料；使用示例标签与示意关联说明，不虚构论文书目。提供独立导入入口，活动及无 DOI 资料按稳定导入标识匹配，有 DOI 资料按标准化 DOI 匹配，关联按唯一组合匹配。首次创建时未来活动为导入时刻后 30 天，历史活动为此前 7 天；重复导入只补缺，不覆盖修改，不移动日期，也不在部署时自动执行。
- **验证测试：** 固定导入时刻验证两场活动日期及每场至少三条真实资料，核对标题、作者和链接来源；重复导入不增加重复数据。修改活动标题、时间、资源书目及关联理由后再次导入，修改均保留；删除一条预置关联后导入只补该缺项。公开标签和示意关联说明存在。

### 10. 实现活动列表只读接口

- **指令：** 按技术栈 Public API contract 实现公开活动列表接口，返回未分页数组和全部规定活动字段，后端按活动 ID 升序。使用聚合获取资源计数，不逐活动查询；内部导入标识、会话及管理员信息不返回。前端仍负责按开始时间分组排序。
- **验证测试：** 匿名请求返回 JSON 数组而非分页包装，字段名称和整数、字符串、布尔值、UTC 时间类型完全匹配；可选文字为空字符串，全空时返回空数组。零资源活动返回数量零，计数准确，增加活动数量不会使数据库查询次数线性增长。

### 11. 实现活动详情只读接口

- **指令：** 详情返回与列表相同的全部活动字段及 resources 数组，每项关联资料采用技术契约规定的扁平字段，区分关联 ID 和资源 ID。按顺序及关联 ID 排列，使用预加载；错误返回包含 detail 字符串的 JSON，缺失活动及未知 API 路径返回 404，服务故障返回不含内部细节的 500。在架构记录引用既有契约，不另选字段结构。
- **验证测试：** 字段及类型完全符合契约；当前活动理由、资源数量及排序正确；缺失作者为空字符串，缺失年份及 DOI 为 null，缺失理由为空字符串。零资料为空数组，不存在活动及未知 API 路径为 JSON 404，模拟故障为安全 JSON 500；不返回 React HTML，查询次数不随资源数线性增长。

### 12. 限制公开接口方法

- **指令：** 将两个公开接口限制为读取、响应头和接口说明请求，不暴露创建、编辑或删除能力，不因使用通用组件而自动开放 CRUD。
- **验证测试：** 匿名用户与已登录管理员的新增、修改和删除请求均为带 detail 的 JSON 405，记录及内容不变；GET 正常，HEAD 只有状态与响应头、无响应体，OPTIONS 只声明 GET/HEAD/OPTIONS 能力。

### 13. 建立 React 项目与本地代理

- **指令：** 建立 JavaScript 版 Vite React 项目，加入 React Router 声明式路由，保留 ESLint，使用普通 CSS。首次安装即锁定前端依赖，用 JSDoc 描述既定 API 类型；相对 API 请求通过本地代理转发 Django。扩展第 04 步 CI，加入前端 lint 和生产构建，不引入跨域包。
- **验证测试：** 前端能打开并读取真实后端，契约中的空值及类型可正确处理；干净安装可使用锁定依赖，lint、构建及前后端 CI 通过；没有 TypeScript、状态管理库或独立 Node.js 后端。

### 14. 建立请求状态与页面路由

- **指令：** 为首页和活动详情建立共用请求模块，检查 HTTP 状态，区分加载、成功、未找到与失败；切换页面时取消过期请求。其他前端地址展示未找到状态。
- **验证测试：** 人为延迟和失败的请求产生对应状态；快速切换两个活动后，旧响应不能覆盖新活动；不存在的活动展示未找到，不误报为空资料；浏览器返回可用。

### 15. 实现首页活动分组

- **指令：** 实现设计文档规定的标题、Upcoming 和 Past 分组及卡片。以一次页面渲染采用的同一当前时刻分组，Upcoming 时间升序、Past 时间降序，时间相同按活动 ID 升序。
- **验证测试：** 用固定当前时刻验证未来、过去和恰好开始的活动归类；验证两个分组排序和同时间排序；只有一个分组有数据以及完全无活动时，均显示规定提示。

### 16. 实现详情页基本阅读

- **指令：** 展示活动信息、资源类型、标题、作者、年份、推荐理由及原文操作。空简介、主题、讲者或推荐理由省略对应区域；原文在新标签页打开；展示示例标识、示意阅读关联及独立项目说明。
- **验证测试：** 浏览活动并打开原文；作者及年份缺失显示规定文案，其他可选内容为空无空标题区域；顺序与接口一致，无资源仍展示活动信息；示例说明存在，新标签页行为有可访问提示。

### 17. 验证第一个里程碑与部署可行性

- **指令：** 从 Admin 添加资料并重新加载公开页面验证可见。先完成最小生产静态集成：Vite 约定前缀、Django 入口模板、WhiteNoise、静态收集、已定义页面路由及迁移成功后启动 Gunicorn；复用第 04 步健康检查。核对免费 Render 的运行时、PostgreSQL 17、构建及账号连接能力，使用已有且已授权的免费资源尝试部署，不依赖后台 Shell 或付费发布前命令。更新架构记录及 AGENTS.md 的实际状态。
- **验证测试：** 本地浏览与 Admin 路径可重复，关闭调试后前端及后台静态文件可加载，直接刷新详情可用，未知 API 返回 JSON 而非 React HTML。核对依赖及免费限制；有远程条件时 Admin、页面和健康检查可响应，无账号连接或免费资源时明确记外部阻塞，不声称已部署。

## 第二阶段：完成搜索与 DOI 管理闭环

建议第 2 天完成本阶段；以约 6–8 小时为预算。

### 18. 实现当前活动内的标题搜索

- **指令：** 在已有资源集合中执行标题包含搜索，忽略大小写及查询两端空格。清空搜索后恢复原始顺序；无资源时不显示搜索框，无结果时提供清空操作。
- **验证测试：** 相同词的大小写变体和带两端空格的查询结果一致；作者名称不会被当作标题命中；其他活动的资料不出现；清空后数量和顺序恢复，无结果文案正确。

### 19. 建立 DOI 输入规范化

- **指令：** 按技术栈规则接受纯 DOI 与 HTTPS doi.org 链接；链接路径只解码一次，不允许其他域名、凭据、显式端口、查询或片段。去掉两端空白并转小写，验证注册者数字与非空无空白后缀，保留合法标点。只请求固定 Crossref 目标下编码后的单个 DOI，不跟随跨主机重定向。
- **验证测试：** 纯文本、链接、百分号编码路径、大小写与两端空白归一到同一 DOI；空输入、错误前缀、无后缀、内部空白及上述禁止链接形式在请求前拒绝。合法后缀标点保留，路径不二次解码；无效输入无网络访问，重定向不能请求任意主机。

### 20. 实现 Crossref 成功响应转换

- **指令：** 在独立服务模块设置连接 3 秒、读取 7 秒超时，按已固定规则转换 Crossref：首个非空标题；来源顺序的个人或组织作者及分隔符；依次取 published-print、published-online、issued 的有效年份；两种资源类型及 crossref 来源。仅接受返回的 HTTP(S) 原文 URL，缺失时要求补充。缺失作者为空字符串、年份为空值，不导入摘要或生成结论。
- **验证测试：** 模拟多标题、多作者、组织作者、缺作者、缺年份、冲突年份、首选年份无效及两类资料响应，验证转换优先级、类型与空值；无效或缺失标题/链接不能直接保存，预览要求补充。核对固定目标及超时，获取过程不创建或修改资源与关联。

### 21. 实现 Crossref 错误转换

- **指令：** 分别处理记录不存在、请求过多、上游错误、无效响应、连接失败和超时。转换为设计文档的提示，保留输入，不自动循环重试，不将内部异常详情暴露给用户。
- **验证测试：** 对上述每种情况模拟失败，检查提示和重试或手动添加入口；每次获取动作最多一次外部请求，确认动作不访问 Crossref；所有失败后资源与关联数量及内容不变。

### 22. 实现原子保存与已有资源复用

- **指令：** 将资源匹配或创建与关联保存放在短事务中。已有 DOI 复用当前数据库书目，不采用预览中的共享字段；已有关联返回原记录，保留原理由及排序。预览后并发新增同 DOI 时也执行此规则，外部请求不进入保存事务。预览结果记录与重复确认入口在第 25 步接入，不在本步依赖尚未建立的表单或会话流程。
- **验证测试：** 直接测试保存服务：新 DOI 创建一条资源及一条关联，加入另一活动只新增关联；重复调用即使含不同理由/排序也保持原记录。关联保存失败时新资源回滚；模拟预览后创建或修改同 DOI 资源，保存仍复用当前数据且不覆盖。

### 23. 验证并发保存

- **指令：** 使用 PostgreSQL、独立数据库连接和协调起点验证竞争保存；将预期唯一冲突在事务回滚后转换为已存在结果，不吞掉其他数据库错误。
- **验证测试：** 两个请求同时向同一活动加入同一 DOI，最终只有一条资源和一条关联；同时加入两个活动，最终只有一条资源和两条关联；请求都获得可解释结果，不留下失败事务状态。

### 24. 加入 Admin DOI 预览页面

- **指令：** 在 Admin 内提供两步表单，始终显示目标活动。先匹配已有 DOI，命中则展示只读数据库书目，只改关联理由与顺序；未命中才获取 Crossref，允许补充缺失字段。使用 Django 数据库会话，每个预览独立随机标识，绑定管理员、会话及目标，成功获取或加载后固定 15 分钟有效。会话更新按技术栈锁定并合并各预览，多个标签页不覆盖；取消仅使对应预览失效。
- **验证测试：** 获取成功、失败及取消均不创建或修改 Resource/EventResource，可写会话；已有 DOI 不调用 Crossref 且书目只读。两个标签页（包括并发获取）分别保留预览，取消其中一个不影响另一个；内部 DOI 或目标身份不能由隐藏字段替换，必需书目缺失时表单校验拒绝确认，第 25 步再验证实际提交入口。

### 25. 接通 Admin 确认保存

- **指令：** 确认接入第 22 步保存能力，重新检查服务器预览、会话、管理员、目标存在性、模型权限、期限及字段。自成功加载起 15 分钟，到期时刻及之后拒绝保存，编辑或重试不延期；取消、篡改或缺失状态同样拒绝并提示重新获取。资源、关联及成功结果在同一短事务保存，有效期内重复确认仅返回已有关联；成功后关联已被移除时要求重新导入，不因旧确认而重建。保存失败保留输入。活动已删除显示规定提示。获取及保存中禁用重复控件。
- **验证测试：** 未确认不写业务数据，确认后公开可见；在期限之前、恰好 15 分钟及之后分别核对成功/拒绝，编辑不延期。取消、其他会话、篡改目标、缺失状态、登录失效及活动被删除均不保存；重复确认不增数据、不改理由/顺序，移除已保存关联后旧确认不重建；模拟会话结果保存失败时新资源与关联也回滚，其他保存失败保留编辑内容且按钮恢复，可重试未过期预览。

### 26. 完成共享元数据修改与排序

- **指令：** 修改共享 Resource 前显示其影响所有引用活动的提示；活动推荐理由和数字顺序仅修改关联记录，使用既有 Admin 表单，不增加拖拽功能。
- **验证测试：** 修改共享标题后两个引用活动都更新且提示存在；只改活动 A 的理由或顺序，活动 B 不变；同值排序仍确定，默认值和自定义值都生效。

### 27. 完成移除关联

- **指令：** 提供从当前活动移除资料的操作和规定确认文案，仅解除关联，不删除共享资源，不提供此流程之外的公开删除入口。
- **验证测试：** 取消确认时数据不变；确认移除后当前活动计数减少，其他活动仍有该资源，共享资源记录仍存在；未授权移除被拒绝。

### 28. 补齐后台权限与 CSRF 验证

- **指令：** 按技术栈的模型权限矩阵检查创建、获取预览、确认、共享编辑、排序、移除及活动删除；所有自定义入口使用 Admin 包装，并在确认时再校验。获取预览及持久化修改均为 CSRF 保护的提交，不增加活动所有权或多租户权限。复查 Resource 删除禁用，包括超级管理员及直接地址。
- **验证测试：** 匿名及分别缺少规定模型权限的 staff 用户被拒绝；预览后撤销权限再确认仍失败。启用真实 CSRF 检查，缺失或伪造令牌被拒绝；GET 不保存/移除业务数据。活动单条和批量删除需确认且保留资源；共享资源单条、批量及直接地址删除均拒绝，业务数据不变。

### 29. 完成真实 DOI 集成验证

- **指令：** 使用开发环境与一个已确认存在的真实 DOI，完成查询、预览、确认、公开阅读与重复导入。核对来源标题、作者和原文地址，继续把 CI 测试保持为模拟外部响应。
- **验证测试：** 真实服务返回的字段与来源一致；第二次导入不增加重复数据；查询不可用时已有公开资料仍可读。网络不可用时记录此项未验证，不用模拟测试冒充真实集成。

### 30. 验证第二个里程碑

- **指令：** 完整走通搜索、DOI 新增与已有书目复用、手动添加、预览过期/取消、共享编辑、关联移除及活动删除，更新 memory-bank/architecture.md 的服务边界、API 契约引用、会话状态、模型权限和测试覆盖，并更新 memory-bank/progress.md。产品行为有调整时同步两份设计。
- **验证测试：** 后端相关测试及已有 CI 全部通过，浏览器路径可重复；架构/进度符合实际接口和验证，未完成事项仍标为待办；两份设计的预览期限、重复规则、删除及交付边界一致。
